### 仅归档边界

- 仅归档不生成 Assertion。
- 模型给出的内容引用必须能在视觉转写或文本预览中连续找到；文件名和路径只能形成 `file_context` Reference。
- 如果模型没有留下内容型 Reference，系统从视觉摘要原文生成一条确定性可检索 Reference，避免只剩目录导航。
- 混用目录推断与图片文字的 Reference 会被过滤，例如不能凭“指导教师”目录推断图片人物身份。

### 内容质量判断

总体上，已通过区域的事实提取质量是可用的，尤其是规则、流程、经费额度、赛事名单、历任会长等内容都保留了时间、数量、条件与例外。比较好的例子包括：

- `region-0066` 将报销的“预算先行、三单合一、数账匹配”保持为一个内聚规则单元，没有拆成大量碎片。
- `region-0021` 正确保留成立日期、BBS 发信记录、筹委会人员及中英文名称，共形成 3 条 Assertion、10 个局部 Fragment。
- `region-0094` 只把“核心干事、普通会员”识别为稳定 Fragment，没有把“低风险试错、中间层级、人力资源、组织力量”等抽象描述全部对象化。

仍有两个实质语义风险：

1. `region-0001` 把中文正式名和英文名都替换成同一个 Fragment token，导致“X 的英文名为 X”。新门禁已能阻止它进入最终产物，但本轮没有重新跑出修正快照。
2. `region-0033` 把“游园会/嘉年华”“游园会”“嘉年华”放进同一个 Fragment。原文只是用斜杠把两类活动并列书写，文档其他位置又把社团游园会与社团嘉年华作为两个活动处理；这个局部分组可能迫使后续全局解析错误合并两个活动。类似地，标题中的斜杠、冒号不能自动视为别名关系，应增加确定性检查或让全局阶段可以拆开可疑组合。

297 个 Fragment 中有 284 个只有一个 surface form，说明局部阶段整体偏保守，没有大面积乱并别名；但也意味着真正的去重高度依赖尚未执行的 Global Object Resolution，本轮无法验证“乒协”28 个局部 Fragment 最终能否稳定归一。

### 稳定性与重试画像

85 个已通过区域共有 263 次记入快照的模型调用：正常每区 3 次，共 255 次，另有 8 次 clean retry。连同未完成区域和网络级尝试，`model-streams` 留下 274 个 attempt 文件、约 228 万字符 thinking：

- Object Fragment Construction：89 个 attempt，约 143 万 thinking 字符，占 62.7%。
- Assertion Discovery：98 个 attempt，约 72.5 万 thinking 字符，占 31.8%。
- 遗漏扫描：86 个 attempt，约 12.4 万 thinking 字符，占 5.4%。

9 个来源触发过 clean retry，其中 8 个恢复成功，问题分为：

- 4 次非法 JSON：字段值漏引号或自然语言 ASCII 双引号未转义；
- 3 次 Reference Assertion 漏必填 `context_dependent`；
- 1 次 Object Fragment surface form 与来源空格不完全一致；
- 1 次 Object Fragment 首次响应正文为空，由保守重试恢复。

clean retry 会重新解释整段内容，不只是修 JSON。例如 `region-0064` 从 2 条 grounded 改为 5 条，`region-0094` 从 1 条改为 2 条。这种恢复虽然能跑通，但会引入不必要的颗粒度随机性。后续更合适的策略是：先对可以确定修复的结构问题做窄修复，只有语义校验失败才整段 clean retry。

遗漏扫描对本轮 85 个通过区域只新增 4 条 Assertion（占最终 138 条的 2.9%）；其中两条是章节用途/章节结构描述，价值偏低。它确实补到了英文名称等内容，但作为每个来源固定执行的一整轮，性价比偏低。该项记录为后续冷启动专项优化，不在当前阶段改流程。

### 长思考并不只由输入长度决定

已观察到三类情况：

1. 实体密集，长思考有明显语义价值。例如 `region-0021` 只有 3 条命题，但要拆分协会中英文名、BBS、发信人与多个人物，共 10 个 Object Fragment；最终结果完整。
2. 抽象边界判断，短文本也会慢。例如 `region-0094` 最终只有“核心干事/普通会员”2 个 Fragment，但需要排除“低风险试错、中间层级、人力资源、组织力量”等非稳定对象；最终保守选择合理。
3. 模型过度审议，慢却没有同步提升结构可靠性。`region-0019` 输入约 1.3k 字，初次与 clean retry 都长思考，最终仍漏掉一条 claim 的必填 `context_dependent`。

当前所有来源阶段都强制 `thinking="enabled"`。固定 Object Fragment 系统提示约 8–9k 字，包含大量例外和否定规则，而单个来源输入通常只有 1–2.3k 字；模型会反复核对规则。现有重复防护能识别逐字循环，不能识别语义上的反复权衡。

本阶段不采用简单“总请求时长上限”，也不测试关闭 thinking 作为替代。后续冷启动专项可考虑把“语义决策长思考”与“schema 小修复”拆开：前者保留 thinking，后者针对确定性校验错误做小范围结构修复，避免重新完整理解原文。

### 名称事实被同一 Fragment 折叠

`region-0001` 初次结果把“正式中文名、英文名”都替换为同一 Fragment token，形成类似“X 的正式名称、英文名都是 X”的语义损失。原因是“同指名称必须同组”与“名称应替换成 Fragment token”在名称事实中存在表达冲突。

已处理：

- 提示明确要求名称事实只用一次 token 指向对象，其余正式名称、英文名、全称、简称、缩写或别名字面值必须保留。
- 新提交和旧 checkpoint 复用都执行同一确定性校验。
- 已添加回归测试，防止旧坏快照被静默复用。

### 输出校验与传输异常

- 观察到 malformed JSON、缺字段和逐字重复；大部分由单次 clean retry 恢复。
- `region-0019` 初次和 clean retry 均只漏 Reference Assertion 的 `context_dependent`。两次 reasoning 都已完成内容判断；第二次甚至明确写出“Reference assertion: doesn't need context_dependent”，说明根因是输出契约歧义，不是图标内容过于复杂。为了保证跑通，最小修复应是：仅当 kind=reference 且字段缺失时确定性补 `false`，grounded 仍保持严格必填。
- `region-0019` 的上游视觉块本身也存在质量问题：MinerU 将 Figure A.1 与 Figure A.2 的说明并在一个 block 中，却只给出一枚蓝色鹿角/火焰徽章的视觉描述；Figure A.3 的文字标识又被识别成 heading。模型因此只能把徽章外观命题标为依赖上下文，无法可靠对应具体 Figure。
- 本轮深度来源语义阶段消费的是 MinerU 已生成的 markdown/OCR/图片描述，并没有直接调用新资料库的 `qwen3.8-reasoner → glm-5.2-107` 两阶段图片链路。因此，普通资料库图片编译已跑通，不能自动证明深度冷启动里的图文块绑定也已解决。
- resume 曾遇到一次模型接口 `ConnectError`，断点未损坏，再次 resume 即可继续。
- 这些异常说明断点恢复是必需能力，不应把一次模型调用失败等同于整批重跑。
