# Echo 资料库与分层处理第一版

## 1. 第一版目标

先解决“文件都保留，但不把每个文件都当作知识编译”。资料库是原始文件层，Shared Brain 是
Object–Assertion 知识层，两者不再被“导入就等于编译”绑定。

当前明确不做：回收站、拖拽、权限、操作审计、原文在线编辑、目录自动同步。

## 2. 数据分层

1. `LibrarySourceBlob`：按 SHA-256 内容寻址的不可变原始内容。完全重复的文件只占一份物理存储。
2. `LibraryNode`：用户可整理的虚拟文件与文件夹，保留名称、位置、原始相对路径和处理档位。
3. `LibraryImportBatch`：一次目录导入的结果与错误边界；导入不表示持续同步。
4. `LibrarySourceProcessingRun`：粗编译或深度处理的一次可恢复运行，保存子阶段 checkpoint 与自动续跑次数。
5. `LibraryPlan`：AI 建议的结构化操作。建议与应用分开，用户批准后才在事务中应用。

## 3. 三个处理档位

| 档位 | 用途 | 第一版行为 |
| --- | --- | --- |
| `catalog` / 仅归档 | 不明用途、低价值、只需保留的文件 | 导入时只存储和索引；基础编译最后尝试低成本文字预览或图片多模态理解。有明确语义时形成 Reference/Object；没有明确语义时只保留文件并明确显示未形成知识结果 |
| `coarse` / 粗编译 | 策划案、通知、一般记录 | 人选定档位后，用单次结构化 AI 调用按原文大主题生成 Reference、可选 grounded Assertion 和关联 Object；不做全局勘探或逐段遗漏扫描 |
| `deep` / 深度冷启动 | 生存手册等稳定、高价值、需要长期复用的来源 | 只从数据库判断是否已有当前结果；新的 PDF 由网页后台依次执行全局勘探、来源语义编译、Global Object Resolution，并在整个任务成功后发布到 Shared Brain |

从 `coarse` 或 `deep` 改回 `catalog` 只改变后续处理选择。重编译采用
“成功后替换”：新结果和跨文件 Object 归并全部成功后，该唯一内容先前发布的
Assertion/Reference/Object 成员才会被新版本原子替换；新结果失败时保留旧的当前版本。
某个 Object 失去最后一个有效来源成员时随旧版本一起删除。

基础编译对外只保留成功和失败两种终态。粗编译不再让模型重新判断档位；至少形成一条
Reference 并标注一个来源明确的 Object 名称才算成功，grounded Assertion 可以为空。服务端负责生成 Object 候选并形成闭环。格式不支持、
解析无可用内容、模型请求最终失败、证据编号无效或 Global Object 候选未完整归并才算失败。
原始文件和 MinerU 解析缓存不参与这次替换。

## 4. 用户交互

资料库工作台采用类文件管理器布局：左侧文件夹树、中间列表、右侧预览与索引信息。人可以直接选择多个文件或整个文件夹导入，也可以新建文件夹、重命名、多选移动、改处理档位和删除。当前使用明确的“移动到”选择器，暂不做拖拽。

删除是带确认的永久删除，文件夹会递归删除。文件树节点删除后，只有没有任何其他节点或处理结果引用同一 `LibrarySourceBlob` 时，才删除数据库 Blob 和磁盘原件；重复文件删除其中一份不会破坏其他位置。正在处理的文件不允许删除。

AI 只能先读取索引元数据，再产生 `LibraryPlan`。`catalog` 文件的文件名和目录不是文件内容证据。AI 建议支持新建文件夹、移动、改处理档位，不支持删除；删除只能由人在 UI 中确认。

当建议涉及多个活动目录时，`listLibrary` 支持一次传入最多 50 个文件夹并递归返回后代节点，可按文件/文件夹、处理档位和路径文字过滤，单次最多返回 1000 项。结果同时包含实际匹配数量和是否截断；AI 必须使用返回的真实节点 ID，不能从历史摘要猜测 UUID，也不应为了取得 ID 逐层反复遍历。

## 5. 基础编译工作快照

`LibraryCompilationJob` 只接收用户在“基础编译”页明确勾选的内容，并在创建时固定所选档位；
未勾选文件继续完整保留，不调用解析器或模型。选择器以 `LibrarySourceBlob.sha256`
为实际工作单元，支持搜索、逐项勾选、全选和批量改档位；默认只勾选已有的深度与粗编译项。
同一内容只处理一次；如果多个文件节点的档位不同，初始建议按
`deep > coarse > catalog` 取最高档位。任务固定按 `deep → coarse → catalog`
执行，使后续阶段能复用深度文件已建立的 Object 语境。
深度文件内部的来源节点默认最多 18 个并行编译；按稳定来源顺序的第一个连续节点完成后，单一 Global Object 归并器即开始消费已完成节点。粗编译和仅归档语义编目阶段均默认同时处理 18 份文件；网页文字模型与冷启动模型均允许最多 18 个请求同时处于 thinking / 流式输出，请求发起时间另外受 RPM 队列限制。

结构化输出或来源校验失败时，当前模型步骤先进行一次完整结果纠正，并单独累计“模型输出纠正重试”；只有该步骤仍失败并退出文件 worker 时，才累计文件级 checkpoint 续跑。

粗编译与仅归档的来源预览先被切成 `S0001` 这类正文/视觉证据块，文件名和路径使用 `F0001` 这类语境块。模型只返回证据编号和 Object 名称；服务端按编号复制精确 `sourceExcerpt`，再将名称精确匹配已有 Object 或生成 `new_candidate`。模型不再输出 `sourceExcerpt`、`objectCandidates`、action 或 Object ID。

`LibrarySourceProcessingRun` 保存当前文件、子步骤、进度、结果摘要和错误；
`LibraryCatalogAssessment` 保存来源预览和 Reference/Assertion/Object 草稿候选；仅归档语义编目
不再保存语义状态或模型推荐档位：Reference/Object 非空即表示形成了可用语义，两者都为空即表示未形成知识结果。任务可在当前文件
完成后暂停，可继续或重试失败项；页面刷新后从数据库恢复进度。

`LibraryCompilationState` 保存资料库当前生效的跨文件 Object 草稿快照。新任务先从这份
快照中移除本次重编译文件的旧成员，再进行新一轮归并；只有完整跑通的成功结果
才会原子替换当前版本。Object 失去最后一个有效来源成员时随之删除。原始文件与按 SHA-256
寻址的 MinerU 解析缓存不受影响。

所有文件完成后，任务增加第四阶段“跨文件 Global Object”。每份文件等价于一个来源叶子：按
`deep → coarse → catalog` 的完成顺序，把文件级 Object 候选逐份归入已有正式 Object 或本任务的
Global Object 草稿。每完成一份文件立即写入 job checkpoint；这一阶段只保存草稿映射，不直接创建、
合并或覆盖 Shared Brain Object。

运行采用自动 checkpoint resume：解析预览、图片视觉转写、深度冷启动各阶段目录、文件级语义结果
以及跨文件 Object 游标都会持久保存。模型、网络或进程异常不把文件终结为 failed，而是使用指数退避
重新排队并从最近 checkpoint 继续；后台每 15 秒写心跳，网页发现中断 worker 后自动恢复，不要求用户
点击“重试失败项”。普通文字、视觉转写和跨文件 Object 模型请求不设固定总时长上限，保留长思考；
真正的请求错误才触发自动退避与续跑。暂停仍在当前文件或当前全局来源完成后生效。

工作快照状态不是操作审计日志。当前 Web 运行时在 Next.js Node 进程中串行执行，所以处理期间应保持服务进程运行。页面刷新不影响任务；若服务进程中断，数据库中的任务与当前运行仍然保留，后续可由独立 Worker 接管。

## 6. 导入与运行

首选在资料库页面点击“导入文件”或“导入文件夹”。网页会分批上传，保留文件夹层级，并为同名项自动增加序号；单文件上限 128 MB。由于浏览器的文件夹选择只提供文件，纯空文件夹不会被网页导入。

终端命令仍作为大批量本地导入入口，并可保留空文件夹：

```bash
pnpm prisma:deploy
pnpm library:import -- "/absolute/path/to/folder"
pnpm library:import -- "/absolute/path/to/乒协生存手册.pdf"
```

导入目录时，每个批次在资料库根目录新建一个来源文件夹；导入单文件时直接在根目录创建文件节点。同名项自动增加序号；普通文件和空文件夹都会保留，符号链接和其他非普通文件会被跳过并在终端警告。

## 7. 图片与多模态边界

图片会完整保留、可在详情栏预览，并可设置处理档位。基础编译的仅归档与粗编译阶段使用两段式处理：`AI_VISION_MODEL` 只接收压缩后的图片并产生 OCR、画面观察和不确定性文字；随后 `AI_MODEL` 只读取这份文字，生成 Reference/Object/Assertion 草稿候选，不再接收原图。视觉文字会先写入处理结果，即使第二阶段失败仍可人工查看。文件名和目录仍只是定位上下文，不会被作为图片事实证据。

图片索引描述保留任务模型、评估时间和文件锚点。只有经人审阅或选为 `deep` 的稳定组织事实才考虑进入正式 Assertion；“有一张可能的合影”本身可以只是草稿图片描述，无需强行成为组织知识。
