# 乒协生存手册迁移审计

> 范围：`USTC_TTA_乒协生存手册.pdf`（35 页）

## 结论

第一批已导入 12 条 `draft` Guideline 和 12 条稀疏关系。这不是“只迁移了很少一部分”，而是有意把手册区分为：

1. 可执行、可复用的指导层内容；
2. 将来应进入状态层的当前事实；
3. 应保留在证据层的历史、原文和附件；
4. 需要当届负责人确认后才可成为指导的候选内容。

这能避免把历史资料、联系人、账号、参考金额和个人叙述误写成永久规则。

## 当前 12 条的覆盖边界

| 已导入主题 | 数据库状态 | 为什么足够进入首批 |
| --- | --- | --- |
| 审批门禁、T-7、T-3 | `draft` | 有明确原文时间节点或门禁。 |
| 预算、报销闭环 | `draft` | 有明确材料、数量和流程要求。 |
| 场地、物资钥匙 | `draft` | 是高频资源与风险检查点。 |

## 不自动导入的下一批候选

下列内容有价值，但需要先确认实际使用方式或当届规则，故不在本次无人值守导入中自动写入数据库：

| 候选 | 暂不自动导入的原因 |
| --- | --- |
| 赛事通知、报名截止与赛程编排 | 手册的报名截止时间是“通常”做法，应由赛事负责人确认后再成为可执行指导。 |
| 现场签到、赛程调度和奖品签领 | 已在大型赛事主流程中概括；只有出现跨赛事复用需求时再拆成独立检查表。 |
| 游园会/嘉年华招新玩法 | 属于经验建议，需结合当年的场地、预算和招新目标。 |
| 线上媒体发布、舆情同步 | 需要确认当前平台、审核人和应急路径，不能沿用历史描述。 |
| 文档归档目录 | 依赖证据层和对象存储的实际目录设计，不能只依据手册假设。 |
| 项目制赋权和开放参与 | 属于组织治理政策，需要当届团队明确风险边界与授权范围。 |

## 下一次扩展的准入条件

只有同时满足下列条件，才从候选变为新的 `draft` Guideline：

1. 能在手册或当届确认材料中找到明确依据。
2. 能写出独立的触发条件、建议动作和完成检查。
3. 不依赖尚未存在的状态字段，或能明确提出新增字段需求。
4. 不把“通常做法”、个人偏好或动态政策伪装成强制规则。
5. 能通过 `pnpm guidance:validate`，并在人工抽查后再发布。
