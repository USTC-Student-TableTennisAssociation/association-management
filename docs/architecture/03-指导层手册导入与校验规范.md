# 指导层手册导入与校验规范

> 状态：首批《乒协生存手册》种子数据规范
> 目标：把手册中的可执行规则、流程、检查表和经验，稳定地导入为**草稿** Guideline，而不是把整份原文塞进数据库。

## 1. 导入边界

《乒协生存手册》属于证据/原始材料层；`prisma/handbook-guidance.data.ts` 是从中抽取、重写、结构化后的指导层种子数据。

首批导入只覆盖架构文档确定的 12 条中粒度 Guideline。每一条都应能独立触发或复用，但不拆成“点击一个按钮”“填写一行表格”这种孤立微任务。

以下内容不能被自动固化为永久指导：

- 当年可能变化的报销额度、财务细则、联系人和审批路径；
- 账号、密码、个人姓名、联系方式；
- 手册中只作为案例、历史背景或个人观点的内容；
- 没有明确依据的固定时限。

例如，手册明确“大型赛事活动前至少 7 天**提交**二课申请”，但并未把它写成“必须在 T-7 前审批通过”。活动真正开展前的审批门禁由“无二课审批不开展活动”单独表达。

## 2. 可复用的提取提示词

下面的提示词适合交给后续负责整理资料的 AI。它不能单独保证正确性，必须与第 3 节的校验门槛一起使用。

```text
你正在为中国科学技术大学学生乒乓球协会维护指导层知识库。

任务：仅根据给定原始材料，提取可复用的 Guideline 草稿；不要把原文全文、个人信息、账号信息或未经验证的推测写入指导层。

数据模型：
- Guideline 的 kind 只能是 workflow、rule、checklist、experience。
- 只可填写 title、kind、contentMarkdown、isMandatory、appliesWhen、suggestedActions、basisNote、status。
- status 必须先为 draft；不得自动发布。
- suggestedActions 只能提出 create_task、request_information、show_checklist、draft_document，不得直接改写活动状态。
- Guideline 之间只使用 contains、triggers、requires、next、exception 连线。

抽取规则：
1. 一条 Guideline 应是可独立触发、可复用、将来可独立修改的规则/流程/检查表/经验；不要拆成孤立微任务。
2. 只有原文明确的硬规则才设 isMandatory=true。经验和培养建议不能伪装成制度。
3. 固定日期、金额、联系人、平台流程如可能随年度变化，写成“以当年官方通知为准”；不得把参考数据写成永久事实。
4. 条件只使用已定义的活动、交接、成员或组织事实字段；未知信息应转为 request_information，而不是自行补全。
5. basisNote 用一句话说明形成依据和页码范围即可；不要求建立精确的文件引用表。
6. 先输出草稿和连线，不写数据库。

输出格式：
A. Guideline 草稿列表：标题、kind、强制性、触发条件、正文、建议动作、依据。
B. 稀疏关系图：只列出有明确业务含义的连线。
C. 不确定项清单：说明原文缺失、政策可能变化或需要人工确认的内容。
D. 自检：逐条说明它是否有原文依据、是否误把动态信息写死、是否试图直接修改状态。
```

## 3. 质量门槛

### 自动校验

`pnpm guidance:validate` 会在不连接数据库的情况下检查：

1. 固定 UUID 是否有效且唯一，首批是否恰好有 12 条。
2. `kind`、`status`、连线类型是否都与 Prisma schema 的枚举一致。
3. 标题、正文、形成依据是否非空；强制规则是否有至少一个待确认动作。
4. 触发条件是否只使用已定义事实字段和支持的操作符。
5. 建议动作是否只提出任务、信息请求、检查表或文档草稿，而没有直接写状态的字段。
6. 连线是否存在、无自环、无重复联合主键，且 `contains` / `next` / `requires` 图中没有循环。
7. 回归场景是否仍命中预期规则：正常大型赛事、临期大型赛事、临期常规活动、活动收尾且材料不完整。

### 人工抽查

自动校验通过后，至少抽查每条草稿的：

- 标题是否把原文含义说准确；
- `isMandatory` 是否过度扩大；
- 条件和建议动作是否与当前系统可获得的状态相匹配；
- `basisNote` 是否足以让维护者回到手册章节核对；
- 动态政策是否被明确标记为需要复核。

通过抽查后，才可以将个别条目从 `draft` 改为 `published`。

## 4. 可恢复的导入流程

种子数据为每条 Guideline 分配了固定 UUID。导入脚本采用以下保护策略：

- 不存在的 UUID：创建为 `draft`。
- 已存在且仍为 `draft`：仅在内容实际变化时更新。
- 已存在且为 `published`：内容相同则跳过；内容不同则报错，绝不静默覆盖人工审核结果。
- 连线按联合主键幂等处理。
- 所有写入在一个数据库事务中完成。

因此中途暂停、网络断开或额度耗尽后，重新执行同一导入不会重复创建记录，也不会覆盖已发布的内容。

正常顺序如下：

```bash
pnpm prisma:generate
pnpm guidance:validate

# 仅当 Prisma 迁移历史已经正常且目标是本机开发库时执行
pnpm guidance:import -- --dry-run
pnpm guidance:import
pnpm guidance:verify
pnpm guidance:import -- --dry-run
```

最后一次演练应显示 0 个新建、0 个更新，证明导入可以安全重跑。共享库或正式库的迁移、导入和发布仍需维护者明确确认。
